# Telegram-бот для пользователей 3x-ui (grammY)

Бот для клиентов VPN на панели [3x-ui](https://github.com/MHSanaei/3x-ui) **3.x** (новый API `/panel/api/clients/*`).
Весь интерфейс живёт **в одном сообщении**: бот редактирует его по кнопкам,
а всё, что присылает пользователь (ссылки, команды), сразу удаляет.

## Что умеет

- 👋 приветственное меню для новых: «Купить подписку», «У меня уже есть подписка»,
  «Статус сервиса», «Поддержка»;
- 💳 покупка и продление с оплатой переводом (см. ниже);
- 📡 статус сервиса: работает ли основной сервер и каждая нода, задержка, нагрузка,
  сколько сейчас онлайн (без IP и технических деталей);
- 📊 статус аккаунта: по каждому инбаунду — активен ли, трафик, срок;
- 🔗 ссылка подписки + QR-код;
- ➕ привязка нескольких аккаунтов, 🔓 отвязка;
- 🔔 уведомления: срок истекает через N дней / истёк, трафик ≥ N% / закончился
  (отдельным сообщением с кнопками «Открыть» и «Закрыть»);
- 👮 админ-команды.

## Как привязываются существующие пользователи

Бот **не хранит свою базу пользователей** — связь хранится прямо в панели,
в поле клиента `tgId` («Telegram ID» в карточке клиента). Поэтому:

1. **Сам пользователь**: открывает бота и присылает ссылку подписки
   (`https://…/<subPath>/<subId>`) или любой свой ключ (`vless://`, `vmess://`, `trojan://`,
   `ss://`, `hysteria2://`…). Бот находит клиента по UUID / паролю / subId и записывает
   его Telegram ID в `tgId`. Email не принимается — его легко угадать.
2. **Админ в боте**: `/link <email> <tg_id>`.
3. **Админ в панели**: вписать Telegram ID в поле клиента — бот подхватит сам.

Защиты: аккаунт, уже привязанный к другому Telegram, перепривязать нельзя
(только админ); не более 5 неудачных попыток за 10 минут.

## Покупка (оплата переводом)

1. Пользователь выбирает тариф. Если у него уже есть подписки, бот спрашивает:
   продлить одну из них или купить новую.
2. Бот показывает сумму и реквизиты (`PAYMENT_DETAILS`) и ждёт скриншот или фото чека
   (файл тоже подходит).
3. Чек уходит всем админам из `ADMIN_IDS` с кнопками **✅ Подтвердить** / **❌ Отклонить**.
4. После подтверждения бот сам:
   - **новая подписка**: создаёт клиента (`/panel/api/clients/add`) с email = username
     в Telegram (или `tg<id>`), сроком на N дней и сразу привязывает его к пользователю.
     Клиент прикрепляется к `NEW_CLIENT_INBOUNDS`, а если они не заданы — ко всем
     включённым инбаундам;
   - **продление**: добавляет дни к текущему сроку (если подписка уже истекла — то от
     сегодняшнего дня) и включает клиента. Если у тарифа есть лимит ГБ, бот выставляет
     лимит и сбрасывает трафик. Бессрочные подписки по сроку не меняются;
   - отправляет пользователю уведомление.
5. Повторное нажатие кнопки ничего не делает. Если активация не удалась, заявка
   снова становится «ожидающей», а админ получает сообщение с ошибкой.

Заявки хранятся в `data/state.json`. Магазин включается, только когда заданы
`TARIFFS`, `PAYMENT_DETAILS` и `ADMIN_IDS`; без них кнопки покупки не показываются.

## Админ-команды

| Команда                                 | Что делает                                      |
| --------------------------------------- | ----------------------------------------------- |
| `/stats`                                | сколько клиентов / привязано, статистика заявок |
| `/orders`                               | заявки, ожидающие проверки                      |
| `/find <email \| tg id \| часть email>` | поиск клиентов                                  |
| `/link <email> <tg_id>`                 | привязать                                       |
| `/unlink <email>`                       | отвязать                                        |

## Запуск

Нужен Node.js 22+.

```bash
cp .env.example .env   # заполнить
npm install
npm run build
npm start
```

Для разработки:

| Команда                                   | Что делает                                                         |
| ----------------------------------------- | ------------------------------------------------------------------ |
| `npm run dev`                             | запуск через tsx с перезапуском при изменениях                     |
| `npm run typecheck`                       | проверка типов                                                     |
| `npm run lint` / `npm run lint:fix`       | ESLint (typescript-eslint, правила с проверкой типов)              |
| `npm run format` / `npm run format:check` | Prettier                                                           |
| `npm run check`                           | всё сразу: формат, линтер, сборка и тесты — то же запускает деплой |

Или в Docker (сборка и тесты внутри образа):

```bash
docker compose up -d --build
```

На сервер — `./deploy/deploy.sh` (собирает и тестирует локально, копирует `dist/` и `.env`,
перезапускает systemd-службу; см. `deploy/xui-telegram-bot.service`).

## Тесты

```bash
npm test
```

- `test/unit` — чистая логика: разбор ссылок, правила продления и уведомлений, конфиг;
- `test/infra` — HTTP-клиент против фейковой панели: CSRF, перелогин, API-токен,
  полное тело `clients/update` (без потери ключей), создание клиента;
- `test/e2e` — **настоящее приложение** (`createApp`) + фейковая панель 3x-ui + перехват Bot API:
  привязка, подписка/QR, отвязка, статус, админ-команды, уведомления, покупка, проверка чеков.
  Каждый отправленный текст проверяется на корректную Telegram-HTML-разметку.

## Архитектура

```
src/
  index.ts            точка входа: конфиг → createApp → запуск
  app.ts              composition root — здесь создаются все зависимости
  config.ts           переменные окружения → типизированный Config
  domain/             типы и чистые правила (без I/O): состояние клиента, продление, уведомления
  lib/links.ts        извлечение uuid/пароля/subId из ссылок и ключей
  infra/
    xui/http.ts       транспорт: cookie, CSRF, логин/Bearer, повторный вход
    xui/api.ts        типизированные эндпоинты 3x-ui 3.x
    xui/dto.ts        сырые ответы API → доменные типы, тело для clients/update
    store.ts          состояние бота в JSON (панели, заявки, уведомления)
  services/           бизнес-логика без Telegram, результаты — размеченные объединения
    clients.ts        репозиторий клиентов с кэшем
    accounts.ts       привязка/отвязка, антиперебор, админ-операции
    shop.ts           тариф → чек → заявка → решение → создание/продление
    status.ts         статус серверов и нод
    notifier.ts       напоминания о сроке и трафике
  bot/                всё, что про Telegram
    bot.ts            сборка бота из сервисов
    navigator.ts      контроллеры: сервис → экран, единая обработка ошибок панели
    orders.ts         доставка чеков админам и решение по заявке
    panel.ts          механика «одного сообщения»
    receipt.ts        проверка файла чека
    callbacks.ts      все callback_data в одном месте
    screens/          чистые функции «данные → сообщение»
    handlers/         тонкие обработчики: событие → navigator → панель
    ui/format.ts      единый стиль сообщений и форматирование
```

Зависимости направлены внутрь: `bot → services → infra/domain`. Сервисы не знают про Telegram,
экраны не ходят в панель, а обработчики не содержат логики.
